# Security policy

## Reporting a vulnerability

Do not open a public issue for a suspected vulnerability or include exploit details, credentials, or personal data in a public discussion. Use the repository host's private security-advisory reporting feature when it is enabled, or contact the current repository owner through their established private channel.

This foundation-stage repository has no published response-time commitment or supported-version policy yet. A maintainer should replace this statement with verified contact and support details before releasing software from the repository.

## Handling rules

- Keep secrets out of commits, issues, pull requests, logs, fixtures, and the memory bank.
- Make security-sensitive changes reviewable and verify them at the relevant boundary.
- Record only sanitized evidence and unresolved external verification gaps.
